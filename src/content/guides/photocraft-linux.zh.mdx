不必把每种包都装一遍。**先按使用方式选格式，再按处理器选文件。** 本文以官方 **v%CURRENT_VERSION%** 发布包为例，补充 FUSE、Flatpak 运行时、本地包依赖及 tar.gz 目录这些容易卡住的步骤。

## 五种 Linux 包先选哪一种

| 你的情况                                       | 先选     | 要接受的取舍                                            |
| ---------------------------------------------- | -------- | ------------------------------------------------------- |
| 只想先试一下，或不想做系统级安装               | AppImage | 一个文件启动；仍可能遇到 FUSE、图形或系统库要求         |
| 已使用 Flatpak，或更看重跨发行版的应用运行环境 | Flatpak  | 先有 Flatpak 和运行时；文件访问受沙盒约束               |
| Ubuntu / Debian，想让系统管理应用与依赖        | DEB      | 依赖必须在当前发行版仓库里可用                          |
| Fedora 或其他兼容 RPM 系统                     | RPM      | 使用该发行版的包管理器；RPM 后缀不保证兼容所有 RPM 系统 |
| 想自行放置文件、并行保存多个版本               | tar.gz   | 手动管理依赖、启动路径和快捷方式                        |

这是选择顺序，不是性能排名。AppImage 不是完整虚拟机，tar.gz 也不表示里面是源码。这里的 tar.gz 是已经编译的桌面程序；GitHub 自动生成的 Source code 压缩包才用于源码构建。

## 确认发行版与处理器

终端运行：

```sh
uname -m
cat /etc/os-release
```

x86_64 对应 Intel/AMD 64 位文件；aarch64 对应 ARM64。不要用改文件名或包格式转换来解决 CPU 不匹配。RISC-V 用户见官方 tar.gz 说明，v0.15.1 README 为该构建标注 **glibc 2.39+**。

不知道从哪开始，可以返回[下载选择器](/#downloads)；若已知发行版并希望使用 DEB/RPM，直接选择下表对应文件。

## AppImage：直接运行与 FUSE 问题

```sh
chmod +x photocraft-%CURRENT_VERSION%-linux-x86_64.AppImage
./photocraft-%CURRENT_VERSION%-linux-x86_64.AppImage
```

有的文件管理器也能在“属性 → 权限”勾选“允许作为程序执行”。新下载的文件可能要重新设置权限。

出现 libfuse.so.2 或“AppImages require FUSE”时，按发行版查 FUSE 2 兼容库：例如 Ubuntu 22.04 使用 libfuse2，Ubuntu 24.04 使用 libfuse2t64。不要把“安装兼容库”误写成替换现有 fuse3。具体操作见 [AppImage FUSE 排查](https://docs.appimage.org/user-guide/troubleshooting/fuse.html)。

无法使用 FUSE 时，当前打包采用支持提取运行的 Type 2 runtime，可尝试：

```sh
./photocraft-%CURRENT_VERSION%-linux-x86_64.AppImage --appimage-extract-and-run
```

它需要额外解压空间，不能替你解决所有系统库问题；也可改选 Flatpak 或发行版原生包。不要用 sudo 启动编辑器来“修复”普通权限报错。

## Flatpak：安装运行时与访问文件

先按发行版说明装好 Flatpak。在终端确认可用后，用本地下载包安装：

```sh
flatpak --version
flatpak install --user ./photocraft-%CURRENT_VERSION%-linux-x86_64.flatpak
flatpak run ai.storyteller.photocraft
```

这不是“在 Flathub 搜索 PhotoCraft”的命令；官方提供的是本地 bundle。打包脚本设置了 Flathub 运行时来源，首次安装可能下载较大的运行时。若提示缺少运行时，先看当前用户配置：

```sh
flatpak remotes --user
```

确认需要添加 Flathub 时，使用：

```sh
flatpak remote-add --user --if-not-exists flathub https://dl.flathub.org/repo/flathub.flatpakrepo
```

然后重试本地包安装，阅读运行时提示。用户级和系统级安装不要混着排查；这里统一使用 --user。

如果应用看不到文件，先用“文件 → 打开”的文件选择器授权访问，确认文件所在位置；不要直接给整个主目录或全系统访问权。Flatpak 沙盒与本机文件管理器的可见范围可能不同。参考 [Flatpak 使用说明](https://docs.flatpak.org/en/latest/using-flatpak.html)及[沙盒权限说明](https://docs.flatpak.org/en/latest/sandbox-permissions.html)。

## DEB 与 RPM：让包管理器处理依赖

Ubuntu / Debian：

```sh
sudo apt install ./photocraft-%CURRENT_VERSION%-linux-x86_64.deb
```

Fedora：

```sh
sudo dnf install ./photocraft-%CURRENT_VERSION%-linux-x86_64.rpm
```

openSUSE 使用自己的工具，例如：

```sh
sudo zypper install ./photocraft-%CURRENT_VERSION%-linux-x86_64.rpm
```

开头的 ./ 表示“当前目录里的本地文件”。相比只用 dpkg 或 rpm 解包，发行版包管理器会尝试从配置的软件源解析依赖。

如果报告依赖不存在或版本过低，先记录完整内容，确认发行版版本和架构。不要用忽略依赖参数硬装，也不要把其他发行版的基础库覆盖进系统；可以改用适合该系统的 Flatpak，或核对上游支持范围。DEB/RPM 安装成功并不意味着你已经添加了自动更新仓库。

## tar.gz：手动解压二进制包

适合需要控制位置、保留多个版本的用户。先查看目录结构：

```sh
tar -tzf photocraft-%CURRENT_VERSION%-linux-x86_64.tar.gz
```

当前官方打包树包含版本顶层目录和 bin、share。解压到自己的独立版本目录，去掉归档的第一层目录：

```sh
mkdir -p "$HOME/Applications/photocraft-%CURRENT_VERSION%"
tar -xzf photocraft-%CURRENT_VERSION%-linux-x86_64.tar.gz --strip-components=1 -C "$HOME/Applications/photocraft-%CURRENT_VERSION%"
"$HOME/Applications/photocraft-%CURRENT_VERSION%/bin/photocraft"
```

保留 bin 与 share 的相对位置，不要只拷贝一个二进制文件。它不自动注册系统包或开始菜单入口，也不自带全部系统库；缺少依赖时按发行版处理。结构依据[官方 Linux 打包脚本](https://github.com/storytold/photocraft/blob/v0.15.1/packaging/linux/package.sh)。

## 按错误定位问题

| 看到的报错                    | 先查什么                                           |
| ----------------------------- | -------------------------------------------------- |
| Permission denied             | 可执行位、目录是否允许执行；不要直接 sudo 运行     |
| Exec format error             | uname -m 与文件架构                                |
| libfuse.so.2                  | AppImage 的 FUSE 2 兼容库或提取运行                |
| Flatpak runtime not installed | 运行时来源与安装范围是否一致                       |
| GLIBC_x.xx not found          | 发行版系统库是否满足该原生包要求                   |
| 空白画布或显卡初始化失败      | 从终端保留输出，查看 Help → System Info 的显卡后端 |
| 应用菜单打开了旧版            | 是否同时存在 Flatpak、系统包和手动解压版本         |

启动后，先用图片副本做打开、保存、导出和重新打开的小测试。图形问题不等于安装包选错；报告时提供发行版、桌面会话、架构、版本和完整错误，见[反馈指南](/photocraft-github)。

## 更新与卸载别混用安装方式

- **AppImage**：保存需要的文档，退出后替换文件；若配置 AppImageUpdate，按其流程更新。删除应用文件不等于删除用户设置。
- **Flatpak**：用 flatpak list --app 检查安装项，查看其来源再决定更新方式；本地 GitHub bundle 不会因为运行 flatpak update 就必然追踪新的 GitHub 发布。卸载使用 flatpak uninstall --user ai.storyteller.photocraft，默认不等于清除所有应用数据。
- **DEB/RPM**：通过安装时使用的包管理器升级或卸载，先预览将修改哪些依赖。
- **tar.gz**：新版本解压到新目录，确认工作后再移走旧版本；更新自己的快捷方式，避免仍指向旧路径。
