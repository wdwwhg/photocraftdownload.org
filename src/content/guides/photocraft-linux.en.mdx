You only need one package format. **Choose the installation style, then the processor architecture.** This guide covers the official **v0.9.0** files and the common gaps between downloading a file and getting a working application.

**Test status:** this site has no recorded Linux installation or Linux application screenshot. The package steps use developer and distribution documentation. Our [recorded Windows test](/photocraft-review#hands-on) is a reference for the sample document only; it does not verify Linux graphics, FUSE, Flatpak or any distribution.

## Which of the five packages should you choose?

| Your situation                                                   | Start with | Trade-off                                                               |
| ---------------------------------------------------------------- | ---------- | ----------------------------------------------------------------------- |
| Try the app without a system installation                        | AppImage   | One file; FUSE, graphics or host-library requirements may remain        |
| Already use Flatpak or want a cross-distribution app environment | Flatpak    | Install its runtime; sandboxed file access can differ                   |
| Ubuntu / Debian with package-managed integration                 | DEB        | Dependencies must exist for your distribution release                   |
| Fedora or another compatible RPM distribution                    | RPM        | Use its own package manager; RPM alone does not guarantee compatibility |
| Control placement or keep versions side by side                  | tar.gz     | Manage dependencies, launch paths and shortcuts yourself                |

This is a workflow choice, not a performance ranking. AppImage is not a complete virtual machine. The listed tar.gz is a compiled desktop archive; GitHub's separate Source code archives are for source builds.

## Identify your distribution and architecture

```sh
uname -m
cat /etc/os-release
```

Use x86_64 for 64-bit Intel/AMD and aarch64 for ARM64. Renaming or converting a package does not change its CPU architecture. The v0.9.0 README specifies glibc 2.39+ for its RISC-V build.

The [download chooser](/#downloads) handles the common choices. If you specifically want a native DEB or RPM, use the corresponding links below.

## AppImage and FUSE errors

```sh
chmod +x photocraft-0.9.0-linux-x86_64.AppImage
./photocraft-0.9.0-linux-x86_64.AppImage
```

Your file manager may offer an executable-permission checkbox. A new download may need that permission again.

For libfuse.so.2 or “AppImages require FUSE,” check the distribution's FUSE 2 compatibility library: Ubuntu 22.04 uses libfuse2; Ubuntu 24.04 uses libfuse2t64. Installing a compatibility library is different from replacing fuse3. See the [AppImage FUSE guide](https://docs.appimage.org/user-guide/troubleshooting/fuse.html).

The current package uses a Type 2 runtime supporting extraction without FUSE:

```sh
./photocraft-0.9.0-linux-x86_64.AppImage --appimage-extract-and-run
```

Allow extra extraction space. This does not resolve every host-library issue; Flatpak or a suitable native package is another option. Do not launch the editor as root to work around a normal permission error.

## Flatpak runtimes and file access

Install Flatpak through your distribution first, then use the local bundle:

```sh
flatpak --version
flatpak install --user ./photocraft-0.9.0-linux-x86_64.flatpak
flatpak info --user ai.storyteller.photocraft
flatpak run --user ai.storyteller.photocraft
```

This does not assume PhotoCraft is listed on Flathub. The bundle script points runtime installation at Flathub; a first install can require a substantial runtime download. If a runtime is missing, inspect the user installation:

These are documentation-based commands, not a captured terminal session. In your own output, check that `flatpak info` identifies **ai.storyteller.photocraft**, the expected architecture and a user installation. Preserve the runtime name and exact error if installation fails; this site has no PhotoCraft Flatpak terminal-output screenshot yet.

```sh
flatpak remotes --user
```

If you need to add Flathub:

```sh
flatpak remote-add --user --if-not-exists flathub https://dl.flathub.org/repo/flathub.flatpakrepo
```

Retry the bundle installation and review its runtime prompts. Keep user and system installations distinct; these examples consistently use --user.

If files are missing from the app, try its File → Open chooser and check the requested location before changing permissions broadly. A sandbox can expose a different view from your host file manager. See [Flatpak usage](https://docs.flatpak.org/en/latest/using-flatpak.html) and [sandbox permissions](https://docs.flatpak.org/en/latest/sandbox-permissions.html).

## DEB and RPM dependency handling

Ubuntu / Debian:

```sh
sudo apt install ./photocraft-0.9.0-linux-x86_64.deb
```

Fedora:

```sh
sudo dnf install ./photocraft-0.9.0-linux-x86_64.rpm
```

On openSUSE, use its own tool, for example:

```sh
sudo zypper install ./photocraft-0.9.0-linux-x86_64.rpm
```

The leading ./ selects a local file. Distribution package managers can resolve dependencies from configured repositories, unlike merely unpacking with low-level tools.

If a required dependency is unavailable or too old, record it and check the distribution release and architecture. Do not force installation by ignoring dependencies or replacing system libraries with another distribution's copies. Consider a compatible Flatpak environment or the project's support requirements. A downloaded DEB/RPM does not itself establish an automatic update repository.

## Extract the tar.gz binary archive

Inspect its layout first:

```sh
tar -tzf photocraft-0.9.0-linux-x86_64.tar.gz
```

The packaging script creates a versioned top directory containing bin and share. Extract into a separate user directory and strip that first level:

```sh
mkdir -p "$HOME/Applications/photocraft-0.9.0"
tar -xzf photocraft-0.9.0-linux-x86_64.tar.gz --strip-components=1 -C "$HOME/Applications/photocraft-0.9.0"
"$HOME/Applications/photocraft-0.9.0/bin/photocraft"
```

Keep bin and share together. This does not register a system package, create your application-menu entry or bundle every system library. The layout comes from the [official packaging script](https://github.com/storytold/photocraft/blob/v0.9.0/packaging/linux/package.sh).

## Match the error to the next check

| Error                                           | First check                                          |
| ----------------------------------------------- | ---------------------------------------------------- |
| Permission denied                               | Executable permission and mount restrictions         |
| Exec format error                               | uname -m versus package architecture                 |
| libfuse.so.2                                    | FUSE 2 compatibility or extraction                   |
| Flatpak runtime not installed                   | Runtime source and user/system scope                 |
| GLIBC_x.xx not found                            | Host-library requirements of the native build        |
| Blank canvas or graphics initialization failure | Terminal output and Help → System Info               |
| Menu launches the wrong version                 | Parallel Flatpak, native and extracted installations |

Test opening, saving, exporting and reopening an image copy. Include distribution, desktop session, architecture, release and exact errors in a [bug report](/photocraft-github).

## Verify one document and record the display session

Record the environment before diagnosing a file problem:

```sh
uname -m
cat /etc/os-release
printf '%s\n' "$XDG_SESSION_TYPE"
```

Keep this output with the package filename, installed version from **Help → About**, and graphics backend from **Help → System Info**. The display session matters: the [v0.9.0 README's Linux notes](https://github.com/storytold/photocraft/blob/v0.9.0/README.md#get-started) document a Wayland drag-and-drop limitation. Use **File → Open** for the first check so dropping a file is not a prerequisite.

1. Open our [practice PNG](/imgs/photocraft/captures/coast-test.png) from a writable user folder. In Flatpak, select it through the application's file chooser.
2. Duplicate its pixel layer and create a separate Levels adjustment with RGB midtone **1.10**.
3. Save a new PSD into that folder, close it and reopen the saved file through the chooser.
4. Inspect the layer stack and Levels value. The Windows reference retained two pixel layers and one adjustment at 1.1; a Linux result has not been recorded here.
5. If this fails, keep the terminal error and identify whether failure occurred at launch, file access, canvas rendering, save or reopen.

The [tutorial](/photocraft-tutorial) supplies the reference screenshot and saved PSD. Those are explicitly Windows captures. For a useful Linux issue, add distribution version, architecture, session type and package format to the failing step. A Flatpak access problem and a native graphics failure can need different fixes even with the same document.

## Updates and removal without mixed installs

- **AppImage:** quit and replace the file, or use AppImageUpdate if configured. Removing the application file is separate from removing user settings.
- **Flatpak:** inspect flatpak list --app and its origin. A local GitHub bundle does not necessarily track new GitHub releases through flatpak update. Remove this user installation with flatpak uninstall --user ai.storyteller.photocraft; this is separate from deleting all application data.
- **DEB/RPM:** use the same package manager for upgrades and removal, reviewing dependency changes first.
- **tar.gz:** extract a new version into a new directory and update your shortcut; remove the old directory only after confirming your work and backups.
