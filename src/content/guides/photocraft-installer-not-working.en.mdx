First record the complete error, your operating system, the package filename and where installation stops. A blocked download, installer error and crash after launch need different checks. These steps reference the reviewed **PhotoCraft v0.9.0** packages. For newer versions, use their own filenames and release notes.

## Choose the failure you actually see

| What you see                                             | Go to                                                        | First check                                       |
| -------------------------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------- |
| Windows Installer error, incompatible app or missing DLL | [Windows setup](#windows-msi-and-portable-launch-failures)   | Architecture, complete extraction and MSI log     |

Verify the download first using the [Windows, macOS and Linux SHA256 commands](/is-photocraft-safe). The [download table](/#downloads) contains exact filenames, sizes and hashes. If the hash differs, obtain a fresh official copy before continuing.

## Windows MSI and portable launch failures

Read **Settings → System → About → System type**. Use x64 for 64-bit Intel/AMD Windows, ARM64 for Windows on Arm, and x86 only for a 32-bit Windows installation. On Windows 11, select x64 or ARM64.

For a verified MSI, Windows Installer can write a diagnostic log during an installation you choose to start:

```powershell
msiexec.exe /i ".\photocraft-0.9.0-windows-x64.msi" /L*V ".\photocraft-install.log"
```

This command launches setup and writes a log in the current folder. Review the install prompts. Keep the first relevant error and the surrounding log lines; a final generic failure alone may hide the cause. Remove usernames, private paths and other sensitive information before sharing logs.

For **Portable ZIP**, use Extract All and keep the entire extracted folder together. Launch `photocraft.exe` from that folder, with `portable.txt` beside it. Running inside a compressed-folder preview or copying only the executable can leave dependencies unavailable. Choose a writable user folder for portable settings.

The v0.9.0 [Windows packaging script](https://github.com/storytold/photocraft/blob/v0.9.0/packaging/windows/package.ps1) describes a statically linked C runtime. If an error names `VCRUNTIME140.dll` or `MSVCP140.dll`, confirm the release and identify the component that requested it before installing anything. Do not download isolated DLLs from third-party sites. See the [Windows guide](/photocraft-windows#missing-dll-or-runtime-messages) for the distinction between bundled files, optional runtimes and graphics failures.

## Windows SmartScreen warnings

A reputation warning is different from a named malware detection or an administrator policy block. Compare the exact downloaded filename and hash, check the publisher details available in the warning and consult the [official release](https://github.com/storytold/photocraft/releases/tag/v0.9.0). Do not assume open source means a signed installer or that a matching hash overrides a security alert.

If a scanner reports malware, retain its detection name and seek a corrected developer release. For a managed work or school device, ask its administrator about a policy block. An MSI and Portable ZIP can both be subject to device policy.

We have no captured PhotoCraft SmartScreen warning or reproduction of its dismissal. The [safety page](/is-photocraft-safe#malware-scan-status) states the available scanning evidence separately from link checks.

## macOS Gatekeeper and damaged app alerts

Use the **Universal DMG** for the desktop app on either Intel or Apple silicon. A CLI ZIP is a different tool. Copy the app to Applications, wait for the copy to finish and launch the installed copy.

| Alert                                                     | Next step                                                                                       |
| --------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| App downloaded from the Internet                          | Confirm the expected app and source before first launch                                         |
| Developer cannot be verified / Apple cannot check the app | Recheck source and hash; use Apple's documented per-app exception only after establishing trust |
| App is damaged and cannot be opened                       | Re-download the correct DMG, verify its hash and recopy the app                                 |
| App will damage your computer / malware detected          | Stop and contact the developer for a corrected release                                          |

[Apple's current guidance](https://support.apple.com/en-us/102445) explains **System Settings → Privacy & Security → Open Anyway** for a trusted app after an attempted launch. The option depends on the actual alert and device policy. Avoid disabling Gatekeeper globally or blindly removing quarantine attributes. A read-only signature check is described in the [macOS guide](/photocraft-macos#read-only-signature-and-launch-checks).

No macOS hardware test or PhotoCraft Gatekeeper screenshot is recorded on this site.

## Linux AppImage and FUSE

Start by recording the distribution and CPU architecture:

```sh
uname -m
cat /etc/os-release
chmod +x photocraft-0.9.0-linux-x86_64.AppImage
./photocraft-0.9.0-linux-x86_64.AppImage
```

Use the aarch64 filename on ARM64. `Exec format error` indicates an architecture or executable-format problem; it is not fixed by installing FUSE. A permissions error can come from an executable bit or a mount restriction.

For `libfuse.so.2` or “AppImages require FUSE,” the [AppImage documentation](https://docs.appimage.org/user-guide/troubleshooting/fuse.html) identifies the compatibility package as `libfuse2` on Ubuntu 22.04 and `libfuse2t64` on Ubuntu 24.04. Check your distribution's package names before installing; keep its FUSE 3 setup intact.

For the reviewed Type 2 AppImage, the documented extraction path avoids mounting through FUSE:

```sh
./photocraft-0.9.0-linux-x86_64.AppImage --appimage-extract-and-run
```

Allow extraction space and retain terminal output. This does not solve a missing graphics driver or an incompatible host library. Do not run the editor as root to work around a normal desktop permission problem. The [Linux package reference](/photocraft-linux) covers native packages and Flatpak runtime checks as alternative installation paths.

These are source-based diagnostics. We have not reproduced a PhotoCraft FUSE error or captured its successful fix on Linux.

## Record a useful issue report

Include the release tag, complete filename, SHA256, OS version, architecture, exact alert and failing step. For a launch or blank-canvas failure, add GPU and rendering information from Help → System Info if the app opens. Attach a real screenshot and the relevant log excerpt after removing private information. Use the [GitHub reporting guide](/photocraft-github) to find the right upstream issue and avoid duplicate reports.
